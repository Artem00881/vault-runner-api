## Verdict

**NOT yet safe for real money** — there are confirmed money-integrity bugs in the
bet path and the operator/real-money path is not wired end-to-end. **The core is
sound:** crash math, the ledger primitive, engine authority, and launch-token
one-time use all verified correct. The gaps are fixable without redesigning the
engine.

## Verified sound (do not regress)
- **Crash math is exact** — `P(crash ≥ x) = 0.97/x`, 97% RTP, no truncation/modulo
  bias (13 hex = 52 bits). Re-derived in BigInt + 1M-round sim + live mainnet RPC
  cross-check. `crash.ts`.
- **Ledger** — idempotent debit/credit, `SELECT … FOR UPDATE`, no negative balance,
  P2002 backstop; well tested. `ledger.service.ts`, `test/ledger.test.ts`.
- **Launch-token one-time use** — `GameSession.launchJti` unique constraint defeats
  replay (the pre-check is advisory; the DB unique index is the real guard).
- **Cash-out integrity** — server-authoritative; crash point never leaks; client
  cannot supply the multiplier.
- **`alg=none` / token forgery without a secret** — NOT exploitable on
  jsonwebtoken@9.0.2 (verified against the library source). Pin `algorithms` anyway.

## Findings

### 🔴 Critical (block real money)

**C1 — Concurrent same-panel `placeBet` double-charges the player ✅**
`src/game/bets.service.ts:59,75,77,96`
Two `place_bet` frames for the same `(round, user, panel)` race: both pass the
unlocked `findUnique` "already_bet" check (`:59`), both debit with **different**
keys because the key is `bet:{randomUUID}:debit` (`:75,77`), the second `bet.create`
hits the `@@unique([roundId,userId,panel])` constraint → P2002 → caught at `:96`
and returned as `bet_failed` **with no refund of the second debit**. Player is
charged twice for one bet; the orphaned debit is never returned.
*Root cause:* idempotency key bound to a per-attempt UUID, not the logical bet;
check-then-act with no lock.
*Fix:* make the debit key deterministic on `(roundId,userId,panel)` so the second
debit dedups in the ledger; on P2002 return `already_bet`.
*Test:* `Promise.all([placeBet(u,'A',100), placeBet(u,'A',100)])` → exactly one bet,
one `bet_debit`, balance `start-100`.

**C2 — Tenant isolation absent on the money path; real-money path not wired ✅**
`src/game/bets.service.ts:45-47`; `src/operator/game-session.service.ts:39`;
`src/game/game.gateway.ts:79-81`
Every bet/wallet op resolves the wallet by `userId + currency:"DEMO"`
(`wallet()` at `:45`), and the socket identity is only ever a **guest JWT** — an
operator launch `GameSession` never becomes the actor that bets. Operator journal
wallets are created with the **operator's** currency (e.g. EUR), so in
`WALLET_PROVIDER_TYPE=operator` mode the bet path `findFirstOrThrow` would **throw**
for any non-DEMO player. There is no operator scoping on any bet/wallet/session
query. ⇒ "go-live" is real multi-tenant identity work on the money path, not an
endpoint swap.
*Fix:* carry operator/session + currency end-to-end (authenticate the session, not
a guest user; resolve the wallet by the session's `walletId`/currency); scope every
bet/wallet query by `operatorId`. Add an operator-mode, non-DEMO bet→cashout
integration test before onboarding any operator.

**C3 — Guest-JWT secret falls back to hardcoded `"dev-secret"` ✅**
`src/auth/auth.module.ts:13` — `secret: config.get("JWT_SECRET") ?? "dev-secret"`.
If `JWT_SECRET` is ever unset/empty, all tokens are signed/verified with a known
string → anyone can mint a token for any `sub`. Not live in prod (1Password injects
it with a `:?` guard), but a silent footgun: any boot bypassing `op-compose.sh`, or
the committed dev `.env` (`JWT_SECRET=test_local_prod_secret_change_me`), downgrades
auth with no failure.
*Fix:* fail closed — throw if `JWT_SECRET` missing/empty; warn if weak; pin
`algorithms:['HS256']`. Rotate the burned dev value before real money.

### 🟠 High

**H1 — Round exposure cap is racy / bypassable by parallel bets ✅**
`src/game/bets.service.ts:64-93`. Concurrent bets all read the same pre-insert
`currentExposure` and all pass `checkRoundExposure`; aggregate round exposure can
exceed `maxRoundExposure`. The bankroll circuit-breaker fails under the load it
exists for. *Fix:* serialize exposure accounting per round (advisory lock on
`roundId`, or a reserved-exposure counter, or a `Serializable` tx).

**H2 — Operator-mode: ambiguous timeout on a WIN claws back won money, no retry 🔶**
`src/wallet/seamless-operator-wallet.ts:128-133`, consumed unguarded at
`src/game/bets.service.ts:137`. Compensating rollback on ambiguous timeout is
correct for a **debit** but wrong for a **credit** (player won, money undone and
not retried); the throw also leaves the bet `active`→`busted` and aborts other due
auto-cashouts in the tick. *Fix:* on a `win` timeout, do not roll back — retry the
idempotent credit / mark `payout_pending` for reconciliation; wrap
`cashOut`/`evaluateAutoCashouts` so one failure can't bust the bet or other players.

**H3 — `Infinity`/`NaN` bet amount throws before the try-block ✅**
`src/game/game.gateway.ts:21` (`z.number().positive()` accepts `Infinity`) →
`src/game/bets.service.ts:54` (`BigInt(Math.floor(Infinity))` throws). Surfaces as
an unhandled rejection in the WS handler instead of a clean `invalid_amount`.
*Fix:* `z.number().finite().positive()` (and `.finite()` on `autoCashout`).

**H4 — Vulnerable dependencies 🔶** `bun audit`: 4 high / 6 moderate (multer, lodash
`_.template`, qs, file-type, @nestjs/core) transitively under NestJS. *Fix:* update
to patched versions; add `bun audit` as a CI gate.

**H5 — `/metrics` and `/health` unauthenticated 🔶**
`src/metrics/metrics.controller.ts`, `src/health/health.controller.ts:31`. Expose
bet/payout/RTP volumes and dependency error strings. Mitigated today (origin is
Cloudflare-only; Prometheus scrapes over loopback) but High the moment access
widens. *Fix:* bearer/ACL on `/metrics`; public `/health` returns `{status}` only.

### 🟡 Medium

**M1 — Double cash-out inflates leaderboard / desyncs `Bet.payout` ✅**
`src/game/bets.service.ts:124-156`. Money is paid once (shared payout key), but a
manual+auto race runs the unconditional leaderboard `UPDATE` and `bet.update`
twice → phantom `total_loot` and `Bet.payout` ≠ credited. *Fix:* claim-the-bet
atomically (`updateMany WHERE id AND status='active'`) and only credit + update
leaderboard if one row was claimed.

**M2 — WebSocket gateway CORS hardcoded `origin:"*"` ✅**
`src/game/game.gateway.ts:35`, regardless of `CORS_ORIGIN`. Any site can open an
authenticated game socket. *Fix:* drive WS CORS from the same `CORS_ORIGIN`
allowlist as `main.ts`.

**M3 — Operator session resolver drops `roundId` 🔶**
`src/operator/game-session.service.ts:64-76` returns no `roundId` →
`seamless-operator-wallet.ts` sends `roundId:""` on every bet/win/rollback. Hurts
operator-side reconciliation/disputes. *Fix:* thread the active `roundId` into the
provider calls.

**M4 — Provably-fair: API verifiability is incomplete 🔶**
`src/fairness/fairness.controller.ts`. `round/:id` omits `epoch`/`commitHash`/
`saltSource`/`targetBlock` and `linkVerified` is always null; exhausted epochs'
commitments are served by no endpoint; no per-epoch seed dump. A third party cannot
reconstruct the full chain-of-custody from public data — a cert blocker. *Fix:* add
`GET /fairness/epochs` and `/fairness/epoch/:epoch/seeds`; include epoch/commit/
block + populated `linkVerified` in `round/:id`.

**M5 — Block-salt oracle quorum counts responders, not configured RPCs 🔶**
`src/fairness/eth-block.ts:71-97`. `need = min(2, urls.length)` over responders → 2
colluding endpoints (others down) can inject a salt; ties resolve by response
order; a 1-RPC config trusts one source. *Fix:* require `floor(N/2)+1` of
**configured** RPCs, fail closed, refuse ties, require ≥3 RPCs in real-money mode.

**M6 — Block-salt: oracle outage silently substitutes a grindable random epoch 🔶**
`src/fairness/fairness.service.ts:47-94`. On rollover with the next (block) epoch
unresolved, control falls to `createEpoch(true)` which mints a random-salt epoch
(salt generated with the seeds, same server ⇒ not grind-proof) and orphans the
pre-committed block epoch; epoch numbers can go non-monotonic. *Fix:* keep the
active epoch / stall betting until the pre-committed salt resolves; never skip the
orphaned block epoch; surface `saltSource` per round; optionally refuse to start a
real-money epoch on random fallback.

### 🔵 Low

- **L1 — `OperatorError` (5xx) comment overstates the "never applied" guarantee** —
  behavior is still safe under operator idempotency; fix the comment.
  `src/wallet/http-operator-wallet.ts:24-28,125`.
- **L2 — `Number(bigint)` on the money path** is exact at demo limits but risks
  >2^53 precision loss for high-minor-unit real currencies (satoshi/IDR).
  Keep payout math in integer space; audit before enabling such currencies.
- **L3 — Simulation report mislabels instant-bust as 3.00% (true 3.96%)** —
  `scripts/simulate-rtp.ts:84`; 3.00% = clamp-from-below mass, 3.96% = P(crash=1.00x).
- **L4 — Real-money "10,000x cap" is a per-bet money cap, not a multiplier cap** —
  the crash multiplier is always capped at 1,000,000x (`crash.ts:18`); document it.
- **L5 — `username`/`displayName` encode `operatorId:playerId`** → can surface on
  the public leaderboard. Use an opaque local id. `game-session.service.ts:29,40`.
- **L6 — WS auth failure silently downgraded to read-only**; per-socket (not
  per-IP) rate bucket lets N sockets multiply throughput. Add a per-IP cap.
- **L7 — `CF-Connecting-IP` trusted but not stripped at the Caddy edge** —
  defense-in-depth only today (CF overwrites it); strip client-supplied value.

## Cross-cutting themes
